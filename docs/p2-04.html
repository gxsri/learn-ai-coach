04 · 羽毛球运动表现分析实战

目标：从 01_pose.csv 走到"一份带指标的报告"。 这一篇不需要显卡，是纯数据处理——也是最容易被做错的一环。

一、你最终能交付什么

outputs/<session_id>/
├── 01_pose.csv          ← 骨架原始数据（每帧每人的 17 点）
├── 02_events.csv        ← 检测到的击球事件列表
├── 03_metrics.json      ← 汇总指标
├── overlay.mp4          ← 带骨架 + 角度的叠加视频
├── curves.png           ← 时序曲线图
└── report.html          ← 一页式报告

session_id 这个东西很重要，不要省。 它是"同一场比赛/同一次拍摄"的唯一标识。 后面做数据划分、做纵向对比，全靠它。没有它，你的评估一定是错的（见本文第六节）。

二、核心思路：先找"击球"，再算"在这一瞬间的动作"

羽毛球的动作分析不是"逐帧分析"，而是"围绕击球的那几帧分析"。

速度
 │                    ╭╮  ← 击球瞬间（手腕速度峰值）
 │                   ╱  ╲
 │              ╭───╯    ╰───╮
 │      ╭──────╯              ╰──────╮
 └──────┴────────────────────────────┴────→ 时间
        准备        挥拍     随挥

所以第一步永远是：把手腕速度的峰值找出来。

三、击球时刻检测

原理

击球瞬间，持拍手的手腕速度是一整个动作里的局部最大值。

import numpy as np
import pandas as pd

def detect_hit_events(df, track_id, wrist_idx=9, fps=30,
                      min_gap_frames=10, min_speed_per_sec=3.0,
                      conf_threshold=0.5):
    """
    从一个人的骨架序列里找出击球事件。

    参数说明：
      wrist_idx       : 用哪只手的手腕。9=左手腕，10=右手腕
      min_gap_frames  : 两次击球至少间隔多少帧（防止一个动作被拆成好几个峰）
      min_speed_per_sec: 速度阈值，低于它不算击球（单位：肩宽/秒）
      conf_threshold  : 关键点置信度低于它，这一帧的点不可信
    """
    person = df[df['track_id'] == track_id].sort_values('frame')
    if person.empty:
        return []

    frames = person['frame'].to_numpy()
    x = person[f'x{wrist_idx}'].to_numpy(dtype=float)
    y = person[f'y{wrist_idx}'].to_numpy(dtype=float)
    c = person[f'c{wrist_idx}'].to_numpy(dtype=float)

    # ① 用肩宽归一化，消除距离/身高差异
    sw = np.hypot(person['x5'] - person['x6'], person['y5'] - person['y6']).to_numpy(dtype=float)
    sw = np.where(sw < 1e-3, np.nan, sw)      # 肩宽算不出来就标 NaN
    scale = np.nanmedian(sw)
    if not np.isfinite(scale) or scale <= 0:
        return []

    # ② 平滑（必须！否则全是噪声）
    x_s = savgol_smooth(x, window=11, polyorder=2)
    y_s = savgol_smooth(y, window=11, polyorder=2)

    # ③ 逐帧速度（单位：肩宽/秒）
    dt = 1.0 / fps
    vx = np.gradient(x_s) / dt
    vy = np.gradient(y_s) / dt
    speed = np.hypot(vx, vy) / scale

    # ④ 置信度太低的帧，速度不可信 → 置 0
    speed = np.where(c >= conf_threshold, speed, 0.0)

    # ⑤ 找局部峰值
    events = []
    last_hit = -10**9
    for i in range(1, len(speed) - 1):
        if speed[i] < min_speed_per_sec:
            continue
        if not (speed[i] >= speed[i - 1] and speed[i] >= speed[i + 1]):
            continue                     # 不是局部最大
        if frames[i] - last_hit < min_gap_frames:
            # 离上一次击球太近 → 保留更快的那个
            if events and speed[i] > events[-1]['speed']:
                events[-1] = {'frame': int(frames[i]), 'speed': float(speed[i])}
                last_hit = int(frames[i])
            continue
        events.append({'frame': int(frames[i]), 'speed': float(speed[i])})
        last_hit = int(frames[i])

    return events

参数怎么定

参数 怎么调
wrist_idx 先搞清楚球员是左手还是右手持拍。背对镜头时容易搞反
min_gap_frames 30fps 下一次挥拍约 0.3-0.5 秒 = 10-15 帧。设太小会把一个动作拆成 2 个峰
min_speed_per_sec 先跑一次，把 speed 曲线画出来，看峰和谷差多少，再定阈值。不要凭感觉设

⚠️ 这段代码里最重要的一行是 speed = np.where(c >= conf_threshold, speed, 0.0)。 没有这一行，一个置信度 0.1 的乱跳手腕会产生一个假峰值，你就多出一次"击球"。

三种信号可以互相校验

信号 原理 可靠性
手腕速度峰值 击球时手最快 高（你主要用这个）
球轨迹方向突变 球被拍击改变方向 高，但需要先做球轨迹追踪（TrackNetV3）
击球声 onset 击球有独特的爆音 高，且最便宜——只要视频有音轨

三种信号对齐到同一时间轴，取交集，是目前最可靠的方案。 part1 里提到的那篇羽毛球论文也强调"球轨迹是主线索"，所以后期加上球轨迹会让击球检测质量上一个台阶。

四、投影角计算

代码

import numpy as np

def angle_at(b, a, c):
    """计算以 b 为顶点的夹角（度）。a、b、c 都是 (x, y) 坐标。"""
    a = np.asarray(a, dtype=float)
    b = np.asarray(b, dtype=float)
    c = np.asarray(c, dtype=float)

    v1 = a - b
    v2 = c - b
    n1 = np.linalg.norm(v1)
    n2 = np.linalg.norm(v2)
    if n1 < 1e-6 or n2 < 1e-6:
        return np.nan                    # 两点重合，算不出角度

    cos = np.clip(np.dot(v1, v2) / (n1 * n2), -1.0, 1.0)
    return float(np.degrees(np.arccos(cos)))

用法（持拍侧是右手时）：

# 右肘角 = 右肩(6) - 右肘(8) - 右腕(10) 三点
elbow = angle_at(
    b=(row['x8'],  row['y8']),
    a=(row['x6'],  row['y6']),
    c=(row['x10'], row['y10']),
)

⚠️ 这个数字是什么，不是什么

它是"画面投影角"，不是生物力学意义上的关节角。

  • 单目 2D 姿态估计的关节角有系统性低估。一项以 3D 光学动捕为对照的研究测得 髋约 −11.2°、膝约 −10.6° 的低估；即使做几何修正，残余误差仍有髋约 4.0°、膝约 3.9°
  • 而且那个结果还是建立在固定机位、固定距离、只有一个矢状面动作的前提上

必须做的：

  1. 报告里写清楚"2D 投影角"，不要写成"关节角度"
  2. 机位在整个项目里保持一致——不同机位的投影角根本不能比
  3. 只做纵向对比（同一个人、同一机位、不同时间），不要跟别人的论文数字比
  4. 如果角度差异在 ±10° 以内，不要下结论

这四句话不是免责声明，是正确使用方法的说明书。 做了这四件事，你的报告是诚实且有价值的工具； 不做，它就是一个看起来很专业的错误。

可算的角

角度 三点 可用于
右肘角 6-8-10 挥拍动作、发力幅度
左肘角 5-7-9 同上
右肩角 8-6-12 手臂抬起高度（近似）
右膝角 12-14-16 蹬地、弓步深度（近似）

算不了的：肩内旋、躯干旋转、髋-肩分离角 —— 这些需要 3D 或绕纵轴的信息， 单目投影里信息上就不存在。

五、场地标定：把像素变成米

为什么必须做

不做标定，你只能输出"像素/秒"，这个数字换一个机位就毫无意义。

需要的真值（背下来）

项目 数值
场地总长 13.40 m
双打场地宽 6.10 m
单打场地宽 5.18 m
网高（中央） 1.524 m
网高（网柱处） 1.55 m
前发球线到网 1.98 m
双打后发球线到端线 0.76 m

做法：单应变换（Homography）

原理一句话：平面上 4 个点就能确定"像素坐标 ↔ 真实坐标"的映射关系。

import cv2
import numpy as np

# ① 在视频里手工点出球场 4 个角（或用球场线检测算法自动找）
#    顺序必须和下面 image_points 一一对应！
pixel_points = np.array([
    [ 320,  180],    # 左上角，画面里选一个真实角
    [ 960,  180],    # 右上角
    [ 960,  620],    # 右下角
    [ 320,  620],    # 左下角
], dtype=np.float32)

# ② 这 4 个角在真实世界的位置（单位：米）。注意和上面顺序严格对应。
#    这个例子是"半边球场"，宽 6.10m，深 6.70m（13.40/2）
world_points = np.array([
    [0.00, 0.00],
    [6.10, 0.00],
    [6.10, 6.70],
    [0.00, 6.70],
], dtype=np.float32)

# ③ 求单应矩阵
H, status = cv2.findHomography(pixel_points, world_points)

# ④ 换算任意像素点到真实坐标
def pixel_to_world(x, y):
    pt = np.array([[[float(x), float(y)]]], dtype=np.float32)
    out = cv2.perspectiveTransform(pt, H)
    return float(out[0, 0, 0]), float(out[0, 0, 1])

怎么知道标定准不准

重投影误差检查：把真实坐标用 H 的逆变换映射回像素，和原始像素点比。

H_inv = np.linalg.inv(H)
back = cv2.perspectiveTransform(pixel_points.reshape(-1, 1, 2), H_inv).reshape(-1, 2)
error = np.linalg.norm(back - pixel_points, axis=1)
print('重投影误差（像素）:', error)
# 应该都在 1-2 像素以内。超过 5 像素说明四个角点选得不好

更实用的检查：用标定后的坐标算一下球场的宽度，看是不是 6.10 米。 差太多就是标定错了。

⚠️ 一个必须诚实说明的限制：单应变换成立的前提是"所有点都在同一个平面上"。 球员的身体是立体的，点在地上是对的，点在空中的高度是算不准的。 想算"击球点离地多高"，严格来说需要额外的假设（比如"脚在场上"来推算身高比例）， 误差会明显变大。要么别做，要么明确标注误差范围。

六、动作分类：两条路，选哪条

路线 A：学术路线（现在不推荐）

ST-GCN、2s-AGCN、CTR-GCN、PoseC3D 这些基于骨架的动作识别方法， 在 NTU-RGB+D 这类数据集上表现很好，但：

  • 它们吃的是大规模标注数据（NTU 有 5 万多段）
  • 公开的、带羽毛球击球类型标签的视频数据集，个人拿不到
  • 有论文尝试过（比如用 Transformer 融合骨架 + 球轨迹做击球类型识别）， 但论文自己也指出：通用骨架动作识别模型会把不同的挥拍动作糊成"击球"一类—— 因为 smash 和 wrist smash 的区别非常细微

结论：这条路的门槛不是算法，是数据。个人项目走不通。

路线 B：工程路线（推荐）

核心思路：不要"学"动作，而是"用可解释的特征 + 简单分类器"。

① 从每个击球事件前后各取 ~1 秒的骨架片段
        ↓
② 提取可解释特征：
   · 击球瞬间的手腕高度（相对肩宽）
   · 击球瞬间的肘角、肩角
   · 手腕速度峰值
   · 挥拍前后的髋中心位移（移动距离）
   · 片段内手腕的运动方向（向上/向下/平）
        ↓
③ 用 sklearn 的 SVM / RandomForest / XGBoost 分类
        ↓
④ 用 DTW 做模板匹配（如果你有"标准动作"的参考片段）

为什么这条更现实：

  • 特征可解释——你能说清楚"为什么判成杀球"（手腕高于肩、速度峰值大、向下挥）
  • 训练数据需求小 —— 几百个样本就能起步
  • 你自己标几十个击球就能开始，而不是等一个几万条的数据集

先用规则，再用模型。 一个经验规则就能抓住大部分情况：

def rough_classify(hit, kp):
    """最粗糙的击球类型判断。先用它跑通，再逐步改进。"""
    wrist_y   = kp['right_wrist_y']
    shoulder_y = kp['right_shoulder_y']
    speed      = hit['speed']

    # 注意：图像坐标 y 向下增大，所以"手腕高于肩"是 y 更小
    if wrist_y < shoulder_y - 0.3 * kp['shoulder_width']:
        return '杀球/高点击球' if speed > 6 else '高远球/吊球'
    return '低手击球（挑球/搓球/平抽）'

先把这条规则跑通，再考虑上模型。 你会发现规则能做到 70-80%， 而剩下的 20-30% 才是机器学习真正要解决的问题。

长什么样的数据是"不能做的"

❌ 用通用骨架动作识别模型直接跑到你的视频上，然后宣称能识别杀球/吊球/挑球。 这几乎肯定是不准的，而你还不知道它不准。

七、评估协议：这一节能让你的项目从"玩具"变成"可用"

⚠️ 最常见的致命错误：按帧随机划分数据

如果你把每帧当成一个独立样本，随机分成训练集和测试集—— 同一个回合的相邻两帧几乎完全一样，它们会被分到训练集和测试集两边。 结果就是准确率虚高十几个百分点，而模型实际一点用都没有。

正确做法：

from sklearn.model_selection import GroupKFold

# ★ 用 session_id / player_id 分组，绝不能按帧随机切
gkf = GroupKFold(n_splits=5)
for train_idx, test_idx in gkf.split(X, y, groups=df['session_id']):
    ...

规则：

划分方式 能不能用
按帧随机切 ❌ 绝对不行
按回合切 ✅ 可以
按比赛 / 按 session 切 ✅ 最好
按球员切（测跨人泛化） ✅ 更严格

📌 从第一步就把 session_id 写进数据里

在 02_extract_pose.py 阶段就写进去，别等到要训练了才想起来。 中间产物（CSV、npz）全都要带 session_id 和 player_id 列。

可信度评估（很少有人做，但很值钱）

检查 怎么做
重复性检验 同一段视频跑两遍，指标差异应该接近 0
机位敏感性 换一个机位拍同一个动作，看指标变化多少——变化大就说明该指标不可靠
关键点误差传递 关键点抖动 ±5 像素时，你的角度会变多少度？算出来写进报告
阈值约定 明确写出"角度差异小于 X° 不下结论"

做了这四项，你的报告就从"技术笔记"升级成"分析报告"。

一份诚实的报告结构：

|---|---|---|---|---|---|

## 观察到的趋势

- 前 10 次击球，右肘角平均 142°，后 10 次平均 128°

- 所有角度均为**画面投影角**，非生物力学真值

"局限"这一节是最重要的。 它让你说的话可信。

九、给 AI 编程助手的提示词

我的目标：从单目固定机位手机视频里算羽毛球击球指标 （击球时刻、击球点画面坐标、持拍侧肘/肩的投影角、挥拍速度、髋中心位移、回合节奏）。

请不要给我 3D 关节角、力矩、地面反作用力、躯干旋转角度——这些单目算不出。 如果我要求了，请先告诉我为什么算不出。

技术栈：ultralytics（yolo26n-pose.pt）+ opencv-python + pandas + numpy。 请先给"每帧骨架 → 置信度过滤 → Savitzky-Golay 平滑 → 手腕速度峰值定击球帧 → 计算角度" 的最小可跑脚本，再谈模型训练。

每个指标都要标注单位和坐标系（像素 / 米），角度必须说明是 2D 投影角。 请主动提醒我做场地标定。

数据划分请默认按 session / 比赛切分，并主动检查有没有同一回合的相邻帧 被分到了训练集和测试集两边。

平滑请用 Savitzky-Golay（不要用移动平均，它会削平我要检测的峰值）， 并告诉我 window 该怎么选、怎么验证峰值没被抹平。

涉及 TrackNetV3 等外部仓库时，不要凭记忆编造仓库路径、权重文件名、命令行参数， 不确定就说不确定，让我自己去核对 README。
