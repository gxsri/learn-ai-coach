工程实现、可视化与部署：把算法变成"能用的东西"

面向：会 Python 基础、主要靠 AI 编程助手写代码、RTX 4060 Laptop 8GB、目标是羽毛球运动表现分析。 本笔记基于 2026 年中的实际版本情况核对（本地实测环境：Python 3.12.10、opencv-python-headless 5.0.0.93、numpy 2.5.1、fastapi 0.140.9、PyYAML 6.0.3）。信息随时间会变，命令请以本机 --version 输出为准。

一句话结论

离线批处理流水线（手机视频 → 抽帧 → 姿态估计 → 骨架叠加视频 + 指标 HTML 报告）比"实时 Demo"容易 10 倍、也更有分析价值；用 OpenCV 读帧、ffmpeg 收尾编码、YOLO11-pose 或 RTMPose 出骨架、matplotlib/plotly 出图、Jinja2 出 HTML 报告，最后用 Gradio 包一层界面即可。

核心概念

  1. 两个"视频 API"分工不同：cv2.VideoCapture 逐帧读取 → numpy 数组，方便挨个喂模型；ffmpeg 是外部命令行程序，负责转封装、重编码、压缩、合并音频。OpenCV 的 pip wheel 自带解码后端，装 opencv 不等于装了 ffmpeg 命令行，两者要分开装。
  2. 视频没有"帧尺寸不匹配"这种宽容：cv2.VideoWriter 写入的每一帧尺寸必须严格等于构造时的 (width, height)，否则静默写不进去（文件 0 字节），不抛异常——这是新手最容易卡住的坑。
  3. 骨架 = 关键点 + 连线表：模型只输出 N 个点的 (x, y, 置信度)，"火柴人"靠你自己定义的连线表画出来（Ultralytics 也仍在推进自定义骨架渲染，见 issue #22542）。COCO 17 点顺序是：0 鼻、1-2 眼、3-4 耳、5-6 肩、7-8 肘、9-10 腕、11-12 髋、13-14 膝、15-16 踝（COCO 关键点定义）。
  4. 像素 ≠ 米：羽毛球分析里"移动距离"必须有场地标定（单应性/四点透视变换）才能变成米，否则只能输出像素位移。
  5. 8GB 显存的关键策略是"离线 + 批处理 + 降级"，不是"跑得更快"：单帧小模型只占几百 MB，真正的瓶颈是你的处理流程会同时开太多东西（多进程读视频 + 多实例模型）。

1. 读出视频元信息（并处理 VFR 陷阱）

import cv2
cap = cv2.VideoCapture(r"D:\data\raw\match.mp4")
fps = cap.get(cv2.CAP_PROP_FPS)                 # 常见 30 / 60 / 120
w   = int(cap.get(cv2.CAP_PROP_FRAME_WIDTH))
h   = int(cap.get(cv2.CAP_PROP_FRAME_HEIGHT))
n   = int(cap.get(cv2.CAP_PROP_FRAME_COUNT))     # 手机 VFR 视频常不准
print(fps, w, h, n, "秒≈", n / fps if fps else "未知")

手机录的视频经常是可变帧率（VFR），CAP_PROP_FRAME_COUNT 会偏。保底做法：老老实实 while cap.read(): 数一遍帧，或用 ffprobe 精确统计（-count_frames 会解码全片，慢但准）：

ffprobe -v error -count_frames -select_streams v:0 -show_entries stream=nb_read_frames,r_frame_rate -of default=nw=1 "D:\data\raw\match.mp4"

3. 画火柴人、角度、尾迹

LINKS = [(5,6),(5,7),(7,9),(6,8),(8,10),(5,11),(6,12),(11,12),
         (11,13),(13,15),(12,14),(14,16)]     # 只用躯干四肢，不画脸，更清爽

def draw_skeleton(img, k, thr=0.3, color=(0,255,0)):
    for a, b in LINKS:
        if k[a,2] > thr and k[b,2] > thr:
            cv2.line(img, k[a,:2].astype(int), k[b,:2].astype(int), color, 2, cv2.LINE_AA)
    for x, y, c in k:
        if c > thr:
            cv2.circle(img, (int(x), int(y)), 3, (0,0,255), -1)

def joint_angle(a, b, c):                     # 计算 ∠ABC（度），如肘角、膝角
    a, b, c = np.array(a[:2], float), np.array(b[:2], float), np.array(c[:2], float)
    v1, v2 = a - b, c - b
    cos = np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2) + 1e-6)
    return float(np.degrees(np.arccos(np.clip(cos, -1, 1))))
  • 角度标注：关节点旁画 f"{ang:.0f}"（cv2.putText 仅 ASCII，中文要换 PIL）；轨迹尾迹用 collections.deque(maxlen=30) 存持拍手腕坐标画渐隐折线，信息量最高。
  • 时序曲线 / 报告：matplotlib 出静态图（中文需设 plt.rcParams["font.sans-serif"]=["Microsoft YaHei"]）；plotly 出可交互 HTML（fig.write_html("curves.html")）；Jinja2 模板把 <video> 与 plotly 的 <div> 拼成一份自包含 report.html，不需要服务器。

4. 交互界面：Gradio / FastAPI / Streamlit 怎么选

方案 启动命令 定位 上手成本
Gradio python app.py（默认 http://127.0.0.1:7860） 上传视频→返回视频/图表，最快 最低
Streamlit streamlit run app.py（默认 8501） 多页数据看板、指标表格 低
FastAPI uvicorn app:app --reload --port 8000 真后端：异步任务、批量、给别的程序调 中高

Gradio 有原生 gr.Video、gr.Plot、队列与进度条，做"上传一段视频→返回分析"最快（Gradio 文档）；要"一次上传一批、后台慢慢算"就用 FastAPI 的 BackgroundTasks。三者不冲突：核心逻辑写成一个纯函数 analyze(video_path, cfg) -> dict，界面层随便换。

  • 每个脚本支持 --config configs/default.yaml，参数不写死在代码里；用 logging 写 logs/，每个 session 产出落在 outputs/<时间戳>/ 便于两次对比。

6. 从"手机视频"到"报告"的完整流水线

  1. 拍摄规范：三脚架固定机位（侧后方 45°），全场入镜、不移动不变焦；优先 1080p60 或 720p120，杀球瞬间的腕速才抓得住。
  2. 01_extract.py：ffprobe 确认帧率 → 按 stride 跳帧（分析用 10–15 fps 足够；只对"击球候选帧"回看全帧率）→ 按 resize 缩到长边 960 → 存 data/interim/。
  3. 02_pose.py：批量跑 YOLO11-pose / RTMPose → 保存关键点 (T, 17, 3) 到 .npz；同时用 model.track(..., persist=True) 做球员 ID 关联（见 Ultralytics tracking）。
  4. 03_report.py：算指标 → 生成叠加视频（可只画击中/起跳关键帧）→ 出曲线 → Jinja2 渲染 report.html。
  5. 可选第 4 步：接 BST: Badminton Stroke-type Transformer（arXiv 2502.21085 / CVPRW 2026 论文）把骨架序列分类成"高远球/吊球/杀球"等球路——骨架动作识别是这条路线上最成熟的公开范式。

建议报告的 5 个指标（均可从关键点序列直接算）：① 场地标定后的移动距离与回位时间；② 髋部纵向起伏检测"垫步/起跳"（杀球骨架关键帧检测范式见 IEEE 10226183）；③ 持拍手腕速度峰值及时刻；④ 弓步膝/踝角度曲线（防伤）；⑤ 站位热力图。顶级选手足法量化研究见 Frontiers。

选型建议（针对 RTX 4060 Laptop 8GB）

  • 姿态模型：先用 yolo11n-pose.pt（yolo pose predict model=yolo11n-pose.pt source=... imgsz=640 half=True），够快够准、生态最全；需要更高精度再考虑 RTMPose 系列（MMPose 生态，安装较重）。不要一上手就选 ViTPose 这类大模型，8GB 显存能跑但吞吐很难受。
  • 精度/速度旋钮：imgsz 640 → 480 是性价比最高的一档；half=True（FP16）显存与速度双收益；batch 8→16 视显存余量调（8GB 上 n 级模型通常很宽裕，别盲目开大）。
  • 加速顺序：PyTorch FP16 → 导出 ONNX（yolo export model=yolo11n-pose.pt format=onnx half=True）用 onnxruntime-gpu 跑（TensorRT EP 文档）→ 需要再快才导 TensorRT engine（format=engine，与 GPU 绑定、换机器要重导）。onnxruntime-gpu 现为 1.30.0 且要求 Python ≥ 3.11（PyPI），CUDA/cuDNN 必须与 wheel 匹配；装不上就先退回 CPU 版 onnxruntime 保证流水线跑通。
  • 显存不够的降级阶梯（按顺序执行）：① 跳帧（stride 2~4）；② 输入 resize 到长边 640–960；③ 关掉显存缓存类开关、把最重的步骤挪到 CPU 只跑关键帧；④ 把"逐帧全图推理"改成"检测一次 + 局部裁剪 ROI 再估姿态"；⑤ 最后才考虑换更小的模型或降低拍摄分辨率。
  • 不要做的事：不要为 8GB 显存搞多进程并行推理（多份 CUDA context 会直接吃掉显存）；不要让 Gradio 请求同步跑长任务（会超时，用队列 + 进度条）。

常见坑

  1. cv2.VideoWriter 写出 0 字节：尺寸不匹配 / fourcc 不支持 / 路径目录不存在，三种原因占九成。写完必查文件大小。
  2. OpenCV 版本代差：opencv-python 已进入 5.0（OpenCV 5.0 公告，迁移指南），DNN 引擎重写（cv2.dnn.ENGINE_NEW），C API 移除。AI 助手给你的 4.x 时代代码可能仍能跑，但涉及 DNN/fourcc 时要按 5.x 核对。本地环境同时装了 opencv-python-headless 时，cv2.imshow 会用不了（headless 无 GUI），分析流水线无所谓，做 Demo 要注意。
  3. 帧率是分析的隐形杀手：fps 读错会让所有速度类指标整体偏移。任何速度指标都应先打印 fps 并人工确认。
  4. VFR 视频：CAP_PROP_FRAME_COUNT / FPS 推不出真实时长，别拿它当进度条分母。
  5. 中文乱码：cv2.putText 不支持中文；matplotlib 需显式指定中文字体。
  6. ffmpeg 命令在 Python 里调不通：subprocess.run(["ffmpeg", ...]) 依赖 PATH；Windows 上更稳的写法是配置里写绝对路径 ffmpeg_path: C:\...\ffmpeg.exe。
  7. 指标不可信：没有帧率校验、没有场地标定、没有置信度阈值过滤的"移动距离/击球速度"只是好看的数字，报告里要写清假设。
  8. Gradio 端口/共享：默认 7860；share=True 会生成公网链接，只用于临时演示，别用于真实数据。

给 AI 编程助手的提示词

  1. 先说清目标产物，而不是手段："输入是一段手机拍的 MP4，输出是①叠加了骨架的视频②一份 HTML 报告，含移动距离/髋部起伏/手腕速度峰值三条曲线。请用 cv2 读帧、ultralytics 出关键点、matplotlib/Jinja2 出报告，把核心逻辑写成 analyze(video_path, cfg) 纯函数。"
  2. 强制核对版本与真实 API："先运行 python -c "import cv2;print(cv2.__version__)" 和 ffmpeg -version 并把结果贴给我；不确定 VideoWriter 的 fourcc 参数在 OpenCV 5 下是否变了，就以官方迁移文档为准，不要凭记忆写。"
  3. 要求每一步自检："每步脚本都要①打印视频的 fps/宽高/帧数并断言 fps>0；②写完视频后断言文件大小 > 1KB；③把中间关键点存 .npz，让我改画图时不用重跑模型。任何一步失败要报出具体原因，不要静默继续。"
  4. 提前说明硬件约束："我是 RTX 4060 Laptop 8GB，代码要默认 imgsz=640, half=True，提供 stride 跳帧和 resize 配置项，并给出显存不够时的降级顺序；不要引入需要编译的依赖（如自己编 OpenCV CUDA）。"
  5. 会踩的坑请主动防："注意：帧尺寸必须与 VideoWriter 一致否则静默失败；中文不能 cv2.putText；VFR 视频的 CAP_PROP_FRAME_COUNT 不可信；像素要经场地标定才能变成米。若这些前提不满足，请在报告里显式标注而不是默默算出一个数。"
