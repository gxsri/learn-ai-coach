05 · 羽毛球专项：数据集、论文做法与可复现指标

定位：本篇不重复 03（姿态估计）、04（骨架时序分析）的技术细节，只回答"这个领域已有什么、论文怎么做、哪些指标你做得出来"。 检索时间：2026-09。所有数据集规模数字均附来源；未核实项显式标注。

一句话结论

羽毛球领域不缺数据集、缺的是"你自己视频上的可信指标"——ShuttleSet / ShuttleSet22 / BadmintonDB 给的是"击球点坐标 + 击球类型"这类战术级标注，TrackNetV3 给的是球轨迹，而论文里那些关节角度、躯干旋转、鞭打时序指标全部来自 3D 运动捕捉，单目手机视频算不出真值；你能做的可信指标只有"画面平面内的角度/位移/时序"这一类。

核心概念

1. 公开数据集（真实规模与出处）

2. 文献常见分析维度

  • 击球类型分类：ShuttleSet 原始分类是 18 类，例如 net shot / return net / smash / wrist smash / lob / defensive return lob / clear / drive / driven flight / back-court drive / drop / passive drop / push / rush / cross-court net shot / short service / long service，另加"正反手""绕头"标记 ShuttleSet 论文。中文语境里的搓球、推球、扑球、挑球、吊球分别对应 net shot、push、rush、lob、drop 一类标签，跨数据集标签体系并不统一，混用会直接污染训练集。
  • 击球点高度与位置：ShuttleSet 存"击球点坐标 + 是否过网以上"，用单应变换映射到真实场地坐标。
  • 挥拍速度 / 角速度：论文用骨架关节角度逐帧微分（见笔记 04），但高精度测量靠标记点 3D 捕捉。
  • 重心转移、准备姿势、回合节奏：重心用髋中心轨迹近似；节奏用回合内击球间隔、连续多拍数等统计量。
  • 步法类型（并步 / 交叉步 / 蹬跨步 / 垫步）：文献里多为人工标注或规则阈值判定，我没有找到公开的、带步法细类标签的羽毛球公开视频数据集——这是一个真实的空白，不要假设"下个数据集就有"。
  • 现有系统级做法：BST 用"变宽切片（击球前/中/后）+ 姿态估计 + 球轨迹 + 场地线检测得到球员位置"，再用 Transformer 跨注意力融合，在 ShuttleSet、BadmintonDB、TenniSet 上超过此前最好结果，并强调球轨迹是主线索而非辅助 BST 论文（CVPRW 2026）、代码；该论文同时点出难点：动作极快且区分细微（smash vs wrist smash）、转播画面有观众/裁判/镜头运动/遮挡、通用骨架动作识别模型会把不同挥拍动作糊成"击球"一类。

3. 杀球的标准生物力学指标，以及单目 2D 的硬边界

生物力学论文的标准量：肩关节内旋角与角速度、肘关节屈伸角、躯干（胸腰段）旋转、髋-肩分离角、鞭打/动力链的近端到远端发力时序、起跳高度、地面反作用力与关节力矩、拍头速度（例如 精英男选手跳杀中持拍臂关节力矩与拍头速度的关系）。这些量需要 3D 运动捕捉（或测力台 + 标记点）。背景数字：羽毛球是球速最快的项目，最快击球纪录为 565 km/h（印度选手 Satwiksairaj Rankireddy，吉尼斯认证）Yonex 官方公告。

单目 2D 为什么算不出：单目姿态估计的关节角存在系统性投影低估，一项以 3D 光学捕捉为对照的深蹲研究测得髋 −11.2°、膝 −10.6° 的低估；即使做了几何约束线性修正，均方根误差仍剩髋 4.0°、膝 3.9°，且该结果建立在固定机位、固定距离、且只有一个矢状面动作的前提上 Frontiers in Sports and Active Living。推到羽毛球：绕身体纵轴的躯干旋转、肩内旋、真正的角速度与"鞭打时序"，单视角在信息论上就不足；力矩、地面反作用力完全没有数据来源。

选型建议（RTX 4060 Laptop 8GB）

  • 姿态：yolo26n-pose / yolo26s-pose（2.9M / 10.4M 参数）足够，8GB 显存可以高分辨率 + 多人同时跑 Ultralytics Pose 文档。
  • 球轨迹：TrackNetV3 输入尺寸小，8GB 能推理；不要同时把大姿态模型和 TrackNet 塞进显存跑实时，分段批处理。
  • 微调：8GB 只做小模型 + 低分辨率 + 小 batch + 梯度累积；yolo26l/x-pose（25.9M / 57.6M）不要碰。
  • 验证协议：ShuttleSet22 官方是按固定划分给的，自己划数据必须按"比赛 / 选手"切，绝不能按帧随机切——同一回合的相邻帧几乎相同，随机切会让准确率虚高十几个点。
  • 单位换算：先解决单应变换与比例尺（场地线当标定物），再谈"米/秒"；否则输出的只是像素/帧。

常见坑

  1. 拿单目 2D 数字当生物力学指标写进结论。角度误差量级见上文；必须写明这是"画面投影角度"，不是真值。
  2. 标签体系串台：ShuttleSet 18 类与中文习惯的杀/高远/吊/挑/搓/推/扑不是一一对应，自己造标签前先对齐定义。
  3. 转播 vs 自录：论文的难点（多人、遮挡、镜头推拉）在自录固定机位里没有，但自录引入的是手机变焦、手持抖动、快门/卷帘畸变。
  4. TrackNet 在快球帧丢点：靠 InpaintNet 修复；但修复段落的"速度"是插值出来的，不能用来算球速。
  5. 数据集划分泄露：按帧切分是新手最常犯、也最致命的一个错。
  6. 标注成本：ShuttleSet 是 6 名专业标注员逐拍标注的规模；个人项目别指望复现同等标注质量，优先用峰值检测 + 人工抽检。
  7. 许可与版权：ShuttleSet 的授权条款需自行核对，转播视频版权不属于数据集。

给 AI 编程助手的提示词

  • 我的目标：用单目手机固定机位视频算羽毛球击球指标（击球时刻、击球点画面坐标、持拍侧肘/肩角、挥拍角速度、髋中心位移、回合节奏），不要给我 3D 关节角、力矩、地面反作用力、躯干旋转角度这些单目算不出的量；如果我问了，请先告诉我为什么算不出。
  • 技术栈请用 ultralytics（yolo26n-pose.pt）+ opencv-python + pandas，先给"每帧骨架 → 平滑 → 手腕速度峰值定击球帧 → 计算角度"的最小可跑脚本，再谈模型训练。
  • 每个指标都要标注单位和"它是什么坐标系下的量"，并提醒我做单应变换标定场地比例尺；角度必须说明是 2D 投影角。
  • 数据划分请默认按"比赛/选手"切分，并主动检查有没有同一回合的相邻帧被分到训练集和测试集。
  • 涉及外部数据集（ShuttleSet / ShuttleSet22 / BadmintonDB / TrackNetV3）时，先让我确认许可与下载方式，不要凭记忆编造仓库路径、权重文件名或命令行参数；不确定就说不确定。
