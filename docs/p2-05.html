05 · 常见坑与调试手册

这一篇是工具书，不用通读。卡住的时候按症状查。 最后一节（怎么让 AI 帮你调试）建议认真读一遍——对你来说那是最高杠杆的一节。

一、先学会读报错（这是唯一必须掌握的技能）

Python 的报错信息看起来很长，但你只需要看两个地方：

Traceback (most recent call last):
  File "extract_pose.py", line 24, in <module>      ← ② 看这里：崩在哪一行
    results = model.track(source=VIDEO, persist=True)
              ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "...\ultralytics\engine\model.py", line 512, in track
    ...
ModuleNotFoundError: No module named 'lap'          ← ① 先看这里：最后一行，什么错

读法：

  1. 先看最后一行 —— 那是错误的类型和描述
  2. 从下往上找到第一个属于「你自己写的文件」的行 —— 那是你的代码出问题的地方。 中间那一大堆是库内部的调用栈，对你没用，全部跳过
  3. 如果最后一行你还是看不懂 —— 把最后一行原文复制去搜索 / 问 AI

这一条能解决你 80% 的卡壳。

二、环境类问题

ModuleNotFoundError: No module named 'xxx'

情况 原因 怎么办
确实没装 — pip install xxx
装过但说没有 你装到了别的 Python 里 见下
装的是另一个名字 库名 ≠ 导入名 例如装 opencv-python，导入 cv2；装 scikit-learn，导入 sklearn

"装过但说没有"是最常见的，通常是因为虚拟环境没激活，或者用 pip 和 python 指向了不同的解释器。

⚠️ 特例：Activate.ps1 报"在此系统上禁止运行脚本"

这是 Windows 上的头号坑，而且它的报错会把你引向完全错误的方向。

.\.venv\Scripts\Activate.ps1
# → 无法加载文件 ...，因为在此系统上禁止运行脚本

发生了什么：PowerShell 的默认执行策略禁止运行 .ps1， 所以虚拟环境根本没有激活。接着敲 python，用的是系统 Python， 于是你看到的是 ModuleNotFoundError: No module named 'pandas' —— 而真相是包装在了 .venv 里，只是你没用它。

怎么修（推荐第 1 种）：

# 1) 不激活，直接调用虚拟环境里的 python —— 最省事，不受执行策略影响
.\.venv\Scripts\python.exe 03_events_and_metrics.py --session walk

# 2) 用 .cmd 快捷方式（.cmd 不受执行策略限制）
.\run.cmd 03_events_and_metrics.py --session walk

# 3) 临时放开当前窗口
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1

# 4) 永久放开当前用户
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

一句话诊断（记下来，以后每次都先跑它）：

python -c "import sys; print(sys.executable)"
# 路径里带 .venv = 对；指向 ...\Programs\Python\Python312\python.exe = 你用的是系统 Python

本教程的脚本已经内置了这个诊断：用错解释器时，它会直接告诉你 "真正的问题不是没装，而是你用错了解释器"，并把两个路径都打出来。

一步诊断：

# 看 pip 装到哪了
python -m pip -V
# 看 python 是哪个
python -c "import sys; print(sys.executable)"

⭐ 永远用 python -m pip install xxx 而不是 pip install xxx。 这样能保证 pip 和 python 是同一个环境。

装了 torch 但 cuda available: False

装成 CPU 版了。修复：

pip uninstall torch torchvision -y
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

注意顺序：一定要先装 torch，再装 ultralytics。反过来的话，ultralytics 会顺手给你装一个 CPU 版 torch。

cv2 相关的一切怪现象

症状：cv2.imshow 不存在 / cv2.VideoWriter 报错 / 某个函数"明明有却没有"。

原因：装了多个 OpenCV 包。opencv-python、opencv-python-headless、 opencv-contrib-python、mediapipe 带的那个——它们共用 cv2 这个命名空间，互相覆盖。

修复：

pip uninstall opencv-python opencv-python-headless opencv-contrib-python -y
pip install opencv-python        # 只留一个

规则：一个环境里只留一个 OpenCV 包。 用 headless 版本就没有 imshow（它是给服务器用的，无 GUI）。

中文路径 / 中文文件名导致读文件失败

Windows 上，某些库（尤其老版本 OpenCV）处理中文路径会失败。

修复：把路径改成非中文，或者用 numpy.fromfile + cv2.imdecode 绕过：

import cv2, numpy as np
img = cv2.imdecode(np.fromfile('D:/视频/测试.jpg', dtype=np.uint8), cv2.IMREAD_COLOR)

最省事的办法：项目路径和文件名全用英文和数字。

三、视频读写问题（OpenCV 的坑最多）

cv2.VideoCapture 读不到帧（cap.read() 一直返回 False）

按顺序检查：

cap = cv2.VideoCapture('badminton.mp4')
print('能不能打开:', cap.isOpened())              # False → 路径错 / 编码不支持
print('总帧数:', cap.get(cv2.CAP_PROP_FRAME_COUNT))  # 0 或 -1 → 文件读不到
print('帧率:', cap.get(cv2.CAP_PROP_FPS))
症状 原因 修复
isOpened() 就是 False 路径写错（最常见） 用绝对路径试一次
打开了但总帧数是 0 编码不支持 用 ffmpeg 转成 H.264 的 mp4
读了几帧就 False 文件损坏 换个播放器验证文件本身

cv2.VideoWriter 写出来的视频是 0 字节 / 打不开

三个必须全对，错一个就静默失败（不报错，但文件是坏的）：

writer = cv2.VideoWriter(
    'output.mp4',                              # ① 路径
    cv2.VideoWriter_fourcc(*'mp4v'),           # ② 编码器（Windows 上用 'mp4v'）
    fps,                                       # ③ 帧率，从原视频读
    (width, height),                           # ④ 尺寸，**必须和 write 的帧一致**
)

排查清单：

  1. 尺寸必须在整个过程中保持不变。 如果你 resize 了帧，write 的尺寸必须跟着改
  2. 尺寸是 (宽, 高)，但 numpy 数组的 shape 是 (高, 宽, 通道) —— 顺序反的！ python h, w = frame.shape[:2] writer = cv2.VideoWriter(path, fourcc, fps, (w, h)) # 注意是 (w, h)
  3. 'mp4v' 在 Windows 上最稳。'XVID' 要配 .avi 后缀
  4. 退出前一定要 writer.release()

视频帧率读出来是 0 或 NaN

用 ffmpeg 修一下，或者手工指定：

ffmpeg -i input.mp4 -c copy -r 30 fixed.mp4

四、YOLO / 姿态估计的问题

首次运行卡住不动

正常 —— 它在下载权重文件（几十 MB）。需要联网。 如果一直下载失败，去 Ultralytics 的 GitHub releases 手动下载，放到当前目录。

CUDA out of memory

按这个顺序降：

  1. 降 batch（8 → 4 → 2 → 1）
  2. 降 imgsz（960 → 640 → 480）
  3. 换更小的模型（m → s → n）
  4. 关掉别的占显存的程序（浏览器、游戏、其他 Python 进程）

骨架"跟不住人" / 跟踪 id 频繁跳变

症状：一个球员在整段视频里出现了几十个不同的 track_id。

检查：

import pandas as pd
df = pd.read_csv('01_pose.csv')
print(df.groupby('track_id')['frame'].agg(['count', 'min', 'max']).sort_values('count', ascending=False))

正常的应该是 2 个 id，各覆盖几千帧。如果是几十个 id 各覆盖十几帧 → 跟踪一直断。

原因和修复：

原因 修复
球员动作太快、模糊 提高快门重新拍摄是唯一根治办法
球员互相遮挡 换跟踪器（tracker='botsort.yaml' 或 bytetrack.yaml）
检测置信度阈值太高，人时有时无 调低 conf
画面里人太多 用 ROI 裁剪，只保留球场区域

算出来的速度高得离谱（几十~几百「肩宽/秒」）

先查是不是把 track_id = -1 的行当成一个球员了。

跟踪器不会给每个检测框都分配 id。-1 是"身份不明的一堆框"， 不是一个人。把它们串成时间序列，不同人的坐标会接在一起， 逐帧差分就产生完全虚假的速度峰值 —— 还会被当成"击球"写进报告。

import pandas as pd
df = pd.read_csv('01_pose.csv')
print('无 id 的行数:', (df['track_id'] < 0).sum(), '/', len(df))

本教程的 03_events_and_metrics.py 默认会剔除这些行。 如果你手动写了处理代码，记得自己加这一步。

实测：341 帧的真实行人视频里，1014 行中有 323 行（31.9%）没有 id。 不剔除的话，会凭空多出一个速度峰值 239 肩宽/秒的"球员"。

实测有效的修法：把 --imgsz 提上去

同一个视频（1920×1080，画面里人比较小），只改推理分辨率：

--imgsz 640（默认） --imgsz 1280
检出总行数 1014 3989
无 id 的行 323（31.9%） 0（0%）
有 id 的 track 11 32

提高分辨率把"无 id"问题彻底消掉了（323 → 0）。 原因很直白：人太小时，检测框本身就在置信度边缘晃，跟踪器无法稳定匹配； 分辨率提上去，框就稳了，跟踪自然跟得上。

代价：track 数从 11 涨到 32（检出了更多本来漏掉的人，同时也更碎）。 这是"漏检"和"过检"之间的取舍，要用叠加视频肉眼确认哪个更接近真实人数。

⚠️ 别用运行时间做对比：上表两次运行的条件不同（640 那次额外开了 --overlay 写视频，1280 那次没开），所以耗时不可比。

判断标准：先看叠加视频数一下画面里到底几个人，再决定该用哪个分辨率。

还有一个更根本的因素：机位角度

同一个视频是俯视角拍的，结果所有脸部的关键点（鼻、眼、耳）置信度都很低 —— 因为 COCO-17 姿态模型是用正常平视照片训练的，从头顶往下看它没见过。

对你的羽毛球项目意味着： - 机位不要架太高、不要从正后方拍 - 正对或侧对球场、大致平视，是骨架质量最好的角度 - 换机位之后，角度类指标不能和历史数据比（投影角依赖机位）

⚠️ 这一步不解决，后面全是垃圾。 不要带着跳变的 id 往下做指标。

关键点明显错位（手画到脚上、骨架扭曲）

原因 修复
索引写错了 检查你的索引常量表。5=左肩，不是右肩
32 点体系的索引套到 17 点上 MediaPipe 是 33 点，YOLO 是 17 点，索引完全不同。混用必错
画面里人太小 提高 imgsz，或者把视频裁剪到球场区域
运动模糊太严重 重拍，提高快门

五、数据与算法问题

CSV 里全是 NaN

按顺序查：

import pandas as pd
df = pd.read_csv('01_pose.csv')
print(df.shape)          # 有几行几列
print(df.head())         # 前几行长什么样
print(df.isna().sum())   # 每列有多少个 NaN
症状 原因
行数 = 0 视频里一个人都没检测到。先拿官方示例图验证模型能用
某些列全 NaN 那些索引的点从来没被检测到（比如脚踝被裁掉了）
稀疏的 NaN 正常 —— 遮挡帧。不要无脑填

算出来的速度是疯狂的数值（比如 10000）

你忘了平滑。 关键点逐帧抖动 ±3 像素，逐帧差分后除以 1/30 秒， 就变成了几百像素/秒的假速度。

修复：先 Savitzky-Golay 平滑，再差分。

找出来的"击球"有几十次，明显不对

阈值定错了。 正确做法是先把速度曲线画出来看：

import matplotlib.pyplot as plt
plt.plot(speed)
plt.axhline(y=你的阈值, color='r', linestyle='--')
plt.savefig('speed_debug.png')

看峰和谷差多少，再定阈值。不要凭感觉设。 另外检查 min_gap_frames —— 设太小会把一次挥拍拆成好几个峰。

指标看起来"太圆整" / 好得不真实

怀疑数据泄漏。 特别是：你的训练集和测试集里是不是有同一个回合的相邻帧？ （见 04-羽毛球运动表现分析实战.md 第七节。）

按帧随机划分是新手最常犯、也最致命的错误。

六、⭐ 怎么让 AI 助手帮你调试（对你最重要的一节）

你说了自己"不会调试"。这没关系——但你得会「喂料」。

AI 助手看不到你的屏幕。它只能根据你给的信息推理。给的信息越准，它一次就修好；给的信息模糊，你们俩会来回十轮。

一个可复制的报错模板

【我做了什么】
执行命令：python 02_extract_pose.py --video test.mp4
（或：运行了 starter/02_extract_pose.py，用的是默认参数）

【我期望什么】
生成 outputs/test/01_pose.csv，里面有每帧的骨架坐标

【实际发生了什么】
（把报错**完整**粘贴在这里，从 Traceback 到最后一行，一行都不要删）

【环境】
- Windows，Python 3.12.10
- torch 2.x.x，cuda available: True
- ultralytics 版本：（贴 python -c "import ultralytics; print(ultralytics.__version__)" 的输出）
- 显卡 RTX 4060 Laptop 8GB

【我已经试过】
（比如：换过绝对路径、重装过 opencv、reboot 过）

【请给我】
1. 这个报错最可能的原因是什么
2. 我需要运行哪条命令来确认这个原因
3. 确认之后怎么修

四条铁律

① 报错要完整，不要只贴最后一行。

最后一行告诉你"是什么错"，但你的代码的行号和文件名在中间。 只贴最后一行，助手只能猜。

② 不要说"它不工作"，要说"它做了什么"。

❌ 没用 ✅ 有用
"跑不起来" "报 ModuleNotFoundError: No module named 'lap'"
"结果不对" "检测出了 47 次击球，但我数了视频里只有约 12 次"
"很慢" "处理 1 分钟的视频用了 8 分钟"
"骨架是乱的" "火柴人的连线连到了错误的位置，左手腕画在了右脚的位置"

③ 让助手先"诊断"，不要它马上"改"。

先不要改代码。请先告诉我：
1. 这个现象最可能的 3 个原因，按可能性排序
2. 每个原因我要运行什么命令来确认/排除
等我确认了再改。

为什么这招有效：AI 很爱直接给一个"修好的版本"，但那个版本改的是它猜的原因。 先诊断，能避免它对着错误的原因改十遍。

④ 给它"可复现的最小输入"。

不要说"我的视频效果不好"——传一个最短的、能重现问题的片段， 或者干脆用合成数据。能稳定重现的问题，才修得好。

一条反直觉但很重要的建议

让助手把调试过程写进文件，而不是只在对话里说。

比如："请把这次排查的结论写进 DEBUG.md，包括：现象、确认的原因、修复方式。"

下次遇到同样的问题，你和助手都能直接翻到答案，而不是重新排查一遍。

七、卡住时的检查顺序（照着走）

① 报错最后一行是什么？          → 复制去搜/AI 问
② 我自己的文件里崩在哪一行？      → Traceback 里从下往上第一个自己的文件
③ 那个变量实际是什么值？          → 加一句 print() 打出来
④ 我的输入是什么？                → print 输入文件的路径和数据 shape
⑤ 简化到最小：换个官方示例图能跑通吗？
   （这一步能立刻区分"环境问题"还是"数据问题"）

第 ⑤ 步是最有用的一招：用官方示例（一张标准测试图、一段示例视频）跑一次。

  • 官方示例也不行 → 环境问题
  • 官方示例可以，我的数据不行 → 数据/参数问题

一个问题被劈成两半，就修得快多了。

八、到哪里找答案

来源 适合
库的官方文档 参数含义、API 用法。永远优先看这个，比博客准
库的 GitHub Issues 具体的报错。搜索报错原文，常常已经有人问过
Stack Overflow 通用 Python/numpy/OpenCV 问题
AI 助手 快速定位、解释报错、给排查步骤。但一定要给它准确的信息，并让它先诊断
中文博客 ⚠️ 最不可靠。AI 领域过时极快，很多教程还在讲几年前的东西。看到具体的版本号和命令，务必去官方文档核对

你会发现本教程反复强调"核对版本"。 这不是强迫症—— 那 6 份调研笔记里，审校环节就抓出了 12 处版本/参数错误和 3 条直接跑不通的命令。 AI 生成的资料、网上的博客，都有这个问题。
