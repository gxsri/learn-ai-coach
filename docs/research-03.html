03 姿态估计（骨架提取）技术全景

面向：羽毛球运动表现分析 / RTX 4060 Laptop 8GB / 以 AI 助手代写代码为主 检索时间：2026-09（版本号与性能数字均来自下方来源链接，未核实的一律标注"未核实"）

一句话结论

羽毛球分析请从 MediaPipe Pose（Tasks API） 入门跑通管线，把 Ultralytics YOLO-pose（yolo11n-pose.pt / yolo26n-pose.pt） 作为正式主力（它一个模型同时给出 2-4 人的检测框和 COCO-17 骨架，还能叠加跟踪 ID），RTMPose/MMPose 留到精度不够时再上；3D 现在只值得"看懂概念"，不值得投入主力时间。

核心概念

1. 六种主流 2D 方案的定位（真实库名/许可）

方案 关键点 安装难度 依赖地狱 许可证 多人
MediaPipe Pose Landmarker（BlazePose） 33 点 + 世界坐标 pip install mediapipe（PyPI 当前 1.0.1） 低 Apache-2.0 ❌ 单主体
Ultralytics YOLO-pose COCO 17 pip install ultralytics（PyPI 8.4.153） 低（自带 PyTorch） AGPL-3.0 ✅ 自顶向下内置
RTMPose / MMPose COCO 17 / 26 / 133 需 mmengine+mmcv+mmdet 版本对齐 高 Apache-2.0 ✅（top-down 管线）
OpenPose BODY_25 / COCO-18 需自行编译 C++/CMake/CUDA 很高 代码可商用但模型有额外限制 ✅ 原生
MoveNet（Lightning/Thunder） COCO 17 TensorFlow Hub / LiteRT 加载 中（TF 版本敏感） Apache-2.0 ❌ 单主体
ViTPose COCO 17 要装 mmcv 1.3.9 + PyTorch 1.9 时代环境 极高 Apache-2.0 依赖检测器

结论先行：许可最省心的是 MediaPipe / RTMPose / MoveNet；YOLO-pose 只要你不闭源商用就没问题（学术、个人分析随便用），一旦做产品必须换 Enterprise 许可或换模型。

2. 精度与速度的真实数字

  • YOLO 官方 pose 表（COCO keypoints val，640 输入）：yolo26n-pose 57.2 mAP50-95 / 2.9M 参数 / 7.6 GFLOPs，yolo26s-pose 63.0，yolo26m-pose 68.8，yolo26x-pose 71.6。n/s 两档在你的 4060 上跑实时毫无压力。
  • RTMPose（COCO AP）：rtmpose-t 68.5、rtmpose-s 72.2、rtmpose-m 75.8、rtmpose-l 76.5、rtmpose-l-384 78.3。
  • 结论：同为"实时档"时，RTMPose-m 的精度明显高于 YOLO-pose-n/s，但仍低于 YOLO26m-pose；YOLO 的优势是"检测+姿态+跟踪"一站式，RTMPose 的优势是同精度下参数更小、更省显存。
  • ViTPose-L（top-down）在 COCO val 达 78.3 AP，ViTPose-G 在 COCO test-dev 达 81.1 AP —— 这是精度天花板，但推理慢、环境老，不是 8GB 笔记本该碰的东西。

3. 骨架定义差异（最容易踩的坑）

COCO 17 点（索引顺序，YOLO/RTMPose/MoveNet 通用）：

0 nose          1 left_eye       2 right_eye      3 left_ear       4 right_ear
5 left_shoulder 6 right_shoulder 7 left_elbow     8 right_elbow
9 left_wrist   10 right_wrist   11 left_hip      12 right_hip
13 left_knee   14 right_knee    15 left_ankle    16 right_ankle

对比其他体系：

  • MediaPipe BlazePose 33 点：在 COCO 17 的基础上增加了 8 个手部点（pinky / index / thumb）和额外脸部点（mouth_left / mouth_right），并额外输出 pose_world_landmarks（以髋部中心为原点的米制 3D 坐标）。
  • OpenPose BODY_25：索引 0 nose、1 neck、2-7 肩肘腕（右前左后）、8 mid_hip、9-14 髋膝踝、15-18 眼耳、19-24 脚部（含 heel/big_toe/small_toe）—— 多了颈部和脚部细节，这是它当年在体育分析里很受欢迎的原因。
  • OpenPose COCO-18：在 COCO 17 之外多加一个 neck（索引 1），整体索引后移。
  • RTMPose/MMPose 支持多种：COCO 17、COCO-WholeBody 133（body+hand+face）、26 点（coco + 脚部）、Animal 17（AP-10K）。
  • MotionBERT 要 H36M-17 格式，和 COCO-17 的排列完全不同，必须先做索引映射再喂进去。

⚠️ 羽毛球场景要注意：COCO 17 完全没有脚部点，只有 ankle。如果你要做"步伐/落地位置/启动脚步"分析，COCO 17 不够用，需要选 BODY_25 或 RTMPose 的 26 点模型（coco+foot）。

4. top-down vs bottom-up 范式

  • Top-down（自顶向下）：先用检测器找出每个人的框 → 每个框单独裁出来跑单人姿态。优点：精度高、几乎没有归属歧义；缺点：人数越多越慢（耗时 ∝ 人数）。YOLO-pose 和 RTMPose 官方管线都是这个范式（RTMPose 常配 RTMDet-nano 做人检测，默认每 5 帧检测一次）。
  • Bottom-up（自底向上）：一次前向出所有人的热力图/关键点，再用 PAF（部位亲和场）或贪心匹配把人拼起来。优点：耗时与人数几乎无关；缺点：人一挤在一起（羽毛球双打交叉换位）就容易拼错人、把手脚接错。OpenPose 是它的经典代表。

羽毛球场景选型（2-4 人、快速移动、运动模糊、互相遮挡）：

  1. 人数少 → top-down 的"随人数变慢"完全不是问题，4 个人也就是 4 次单人推理，反而拿到了高精度和"绝不串人"的保证。所以别犹豫：选 top-down。
  2. 用 YOLO-pose + model.track() 给每个人一个稳定的 track id，这样"1 号球员的骨架"在整段视频里是连续的，跨帧姿态曲线才不会被张冠李戴。
  3. 运动模糊没有银弹：能控制拍摄就提高快门（≥1/1000s）、缩短曝光；不能控制就靠后处理——对关键点做置信度过滤 + Savitzky-Golay 或 One-Euro 滤波平滑，别对原始抖动序列直接算角速度。
  4. 遮挡时用置信度阈值丢掉低分点，别把 score=0.1 的手腕当成真值去算击球角度；缺失帧做插值并打标记。

可执行的最短路径（真实命令）

# 环境（Python 3.10/3.11/3.12 都在 mediapipe 支持范围内）
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install ultralytics mediapipe opencv-python

A. YOLO-pose 最小可运行（推荐先跑这个，一次拿到 2-4 人骨架 + id）

from ultralytics import YOLO

model = YOLO("yolo11n-pose.pt")     # 首次运行自动下载；也可换 yolo26n-pose.pt
results = model.track(source="badminton.mp4", persist=True, save=True)

for r in results:                       # 逐帧
    if r.keypoints is None:
        continue
    xy = r.keypoints.xy                 # [人数, 17, 2] 像素坐标
    conf = r.keypoints.conf             # [人数, 17] 每点置信度
    ids = r.boxes.id                    # [人数] 跟踪 id，用来区分球员
    # 例：取 1 号球员左肩 idx5 / 右肘 idx7 / 左腕 idx9 计算肘关节角

关键点顺序见上文 COCO 17 表：kpt[5] = 左肩、kpt[7] = 左肘、kpt[9] = 左手腕。

B. MediaPipe 最小可运行（单主体，最快跑通视觉验证）

import cv2, mediapipe as mp
from mediapipe.tasks import python as mp_python
from mediapipe.tasks.python import vision

base = mp_python.BaseOptions(model_asset_path="pose_landmarker_full.task")
opts = vision.PoseLandmarkerOptions(base_options=base, running_mode=vision.RunningMode.VIDEO)
landmarker = vision.PoseLandmarker.create_from_options(opts)

cap = cv2.VideoCapture("badminton.mp4")
idx = 0
while cap.isOpened():
    ok, frame = cap.read()
    if not ok:
        break
    rgb = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)
    mp_img = mp.Image(image_format=mp.ImageFormat.SRGB, data=rgb)
    res = landmarker.detect_for_video(mp_img, int(idx * 1000 / cap.get(cv2.CAP_PROP_FPS)))
    if res.pose_landmarks:
        pts = res.pose_landmarks[0]         # 33 个归一化点，x/y ∈ [0,1]
        world = res.pose_world_landmarks[0] # 33 个米制 3D 点（髋部为原点）
    idx += 1
cap.release()

注意 MediaPipe 的 .task 模型文件需按官方文档下载，detect_for_video 要求时间戳单调递增（毫秒）。

C. RTMPose（精度不够时的升级路径）

pip install rtmlib          # 免 mmcv 的封装，包名与 API 请在安装后核对

RtmLib 支持纯 Python 推理（ONNXRuntime / OpenCV / OpenVINO 后端），不必配置 mmcv 全家桶；如果坚持走原版 MMPose，必须按 mmpose / mmengine / mmcv / mmdet 的版本对应表安装，这是新手劝退率最高的一步。

D. 8GB 显存的取舍

  • yolo11n-pose.pt / yolo26n-pose.pt：显存占用极小，1080p 视频离线批处理完全没压力（大约几 MB 权重 + 推理激活）。
  • 想要更高精度：yolo11m-pose / yolo26m-pose（25.9M / 21.5M 参数）在 8GB 上也跑得动，但建议把 imgsz 保持在 640-960，别一上来就 1280。
  • 别同时把 ViTPose-L、SMPL 系、大 batch 加载器塞进显存；8192 MiB 的笔记本卡还要留给系统和浏览器。

选型建议（针对 8GB 显存 + 羽毛球）

  1. 第一周：只学 MediaPipe Pose，把"视频 → 33 点 → 画骨架 → 存 CSV"跑通。它的价值是让你在几小时内看见结果、建立直觉。
  2. 第一到第二周：切到 YOLO-pose + track，这是你真正的生产管线。理由：多人、自带 id、安装只有 pip install ultralytics、COCO 17 的文档和可视化代码到处都是。
  3. 真正分析羽毛球时：如果发现手腕/脚踝精度不够（击球点、步伐分析），再引入 RTMPose-m 做单人 ROI 精修 —— 用 YOLO 出框，把框裁出来喂给 RTMPose，兼顾速度与精度。
  4. 不要现在碰的：OpenPose（编译地狱）、ViTPose（环境老旧）、自训练 pose 模型（你没有标注数据）。
  5. 选型速记：单人在场、要快、要省事 → MediaPipe；多人、要 id、要工程化 → YOLO-pose；要论文级精度、愿意折腾 → RTMPose/MMPose。

3D 姿态估计：现在到什么程度，值不值得学

  • MediaPipe BlazePose 3D：直接给你 33 个 pose_world_landmarks（米制，髋部原点）。这是"伪 3D"——单目估出来的相对深度，尺度靠人体先验猜，抖动明显、绝对位置不可信。零成本，适合做角度趋势的定性观察。
  • MotionBERT（ICCV 2023）：把 2D 序列"提升"到 3D 的 Transformer，官方 repo 提供 pretrained（162MB）和 MotionBERT-Lite（61MB）。H36M-SH 上 MPJPE：scratch 训练 39.2mm，fine-tune 后 37.2mm。输入是 H36M-17 格式、最多 243 帧，环境写死 Python 3.7 + PyTorch 1.9 + CUDA 11.6 —— 这是典型的"论文复现环境"，和你的新显卡驱动大概率要打一架。
  • SMPL 系（参数化人体网格）：输出的是形状+姿态参数和完整网格，是"动作捕捉级"的路线（常见组合是 RTMPose/RTMW + MotionBERT + SMPL）。生态在 MMPose 侧（mhuman3d 等），涉及模型许可、坐标对齐、渲染，学习曲线是 2D 的数倍。

判断：不值得现在学，但值得现在"知道"。 原因有三：（1）你的羽毛球指标（击球点高度、膝关节角度、躯干扭转）在 2D + 单应性变换后已经能算，且误差来源主要在拍摄和关键点置信度，不在缺失的第三维；（2）3D 提升模型的误差和抖动会直接污染你的"角度曲线"，你很难判断是运动员变了还是模型抖了；（3）等 2D 管线和指标体系稳定后，MotionBERT 只需要接在你的 2D 输出后面，是个可插拔的增量，不是必须重做的地基。

常见坑

  1. 关键点索引搞错：COCO-17 的 5 是左肩不是右肩；把 33 点的 MediaPipe 索引直接套到 COCO 17 的代码上，画出来的骨架会荒谬地连错。写代码时用常量表而不是魔法数字。
  2. 坐标空间混淆：MediaPipe 输出的是归一化坐标（乘视频宽高才是像素）；YOLO 的 keypoints.xy 已经是原图像素坐标；OpenPose 的 x,y,c 可以按 --keypoint_scale 变成多种尺度。绘图前先统一。
  3. kpt_shape: [17, 3] 里的第三个数是 visible 不是 z。别把可见性当成深度去算 3D。
  4. 左右不分：模型预测的 left/right 是"人体自身的左右"，当球员背对镜头时，画面里在左边的是他的右手。做左右手技术统计时必须以躯干朝向校正。
  5. 把检测框当姿态用：羽毛球扣杀时手臂高举、腿大幅伸展，人体框会剧烈变化；用框宽高当"身高"去归一化尺度会引入巨大误差，应该用肩宽或髋宽（肩 5-6 / 髋 11-12 的距离）做尺度基准。
  6. YOLO 权重文件名写错：最新版 Ultralytics 默认文档已经切到 yolo26* 系列（如 yolo26n-pose.pt），老教程里的 yolov8n-pose.pt/yolo11n-pose.pt 仍然在 release 里存在（v8.3.0 资源列表可查），但不要混用配置和权重。首次运行会自动下载，需联网。
  7. AGPL-3.0 许可风险：Ultralytics 是 AGPL-3.0，个人/学术分析没问题，一旦你要做 App 或提供网络服务，必须考虑开源义务或买 Enterprise 许可。

给 AI 编程助手的提示词

我在用 Python 做羽毛球视频的多人姿态估计（画面里 2-4 人、快速移动、运动模糊、有遮挡），显卡是 RTX 4060 Laptop 8GB。请用 Ultralytics YOLO-pose（yolo11n-pose.pt 或当前版本的 yolo26n-pose.pt）配合 model.track() 写脚本，输出每帧每人的 COCO-17 关键点像素坐标、置信度、跟踪 id，并保存为 CSV；请显式写清楚哪些索引对应左肩(5)/右肘(7)/左腕(9)/右髋(11)/左膝(13)/左踝(15)，不要凭印象编造索引。 关键点置信度低于阈值时留空不要插值填补，并单独输出一列标记该帧是否为"可疑帧"；不要为了让曲线好看而静默平滑。 请先确认库名、模型权重文件名、API 参数在当前安装版本中真实存在（必要时先打印 ultralytics.__version__），不要使用不存在的模型名或参数。 注意：Ultralytics 是 AGPL-3.0，请说明我的用途是否触发开源义务；另外不要建议我一开始就上 MMPose/mmcv 栈或 3D 提升模型，先用最小可运行版本验证画面里能不能稳定跟住这 2-4 个人。
