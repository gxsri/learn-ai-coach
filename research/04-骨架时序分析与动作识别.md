# 04 · 骨架时序分析与动作识别

> 面向：会用 AI 助手写代码、有 RTX 4060 Laptop 8GB、目标做羽毛球运动表现分析的学习者。

## 一句话结论

几百段自录视频、无标注时，**学术路线（ST-GCN / CTR-GCN / PoseC3D）不是你的训练目标**；能跑通并给出可解释反馈的是工程路线——骨架降维成关节角度 / 角速度 / 相对位移 / 重心轨迹，滑窗 + 峰值检测定位击球瞬间，再用 DTW 模板匹配或 sklearn 分类器做小样本分类。

---

## 核心概念

### 1. 骨架序列长什么样

- **NTU-RGB+D 格式**：官方数据是每帧存 `bodyID` + 25 个关节的 3D 坐标，整个动作序列 ≈ `(帧数, 25, 3)`；用于 GCN 时按 `(C, T, V, M)` 组织（C=坐标/joint-bone 通道，T=帧，V=关节，M=人数）[NTU-RGB+D 官方仓库](https://github.com/shahroudy/NTURGB-D)。
- **MediaPipe 格式**：33 个关键点，`world_landmarks` 是以髋部中心为原点的米制 3D 坐标，比 2D 像素坐标更适合算角度[MediaPipe Pose Landmarker (Python)](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/python)。

两套格式关节数不同，**跨格式搬运必须写映射表，不能直接喂给预训练模型**。

### 2. 学术路线吃什么

| 方法 | 输入表示 | 代表精度（NTU60 XSub） |
|---|---|---|
| ST-GCN | 图序列 `(C,T,V,M)` | joint 88.95 / 四流 92.34 |
| 2s-AGCN | joint + bone 双流 | joint 88.60 / bone 91.59 / 四流 92.34 |
| STGCN++ | 同 ST-GCN，架构改良 | joint 89.29 / bone 92.30 |
| PoseC3D | 3D 热力图体（不再是图） | keypoint 93.6 / fusion 94.0 |
| CTR-GCN | 图 + 通道级拓扑细化 | ICCV 2021，[论文](https://openaccess.thecvf.com//content/ICCV2021/papers/Chen_Channel-Wise_Topology_Refinement_Graph_Convolution_for_Skeleton-Based_Action_Recognition_ICCV_2021_paper.pdf) |
| Hyperformer | 超图 + Transformer | 见 PYSKL 系列工作 |

以上数据来自 [MMAction2 Skeleton Model Zoo](https://mmaction2.readthedocs.io/en/stable/model_zoo/skeleton.html)（文档版本 1.2.0）。**注意这些数字的训练配置是 8 张 GPU、100 帧均匀采样、"10 clips" 测试协议**——这是几十万样本规模下的成绩，不是几百条视频能复现的。

### 3. 工程路线的可解释特征

- **关节角度**：`θ = arccos( (a·b) / (|a||b|) )`，a、b 是以某关节为顶点指向两侧的向量；羽毛球重点看持拍侧肘角、肩角、躯干扭转角。
- **角速度**：角度逐帧差分。抖动大说明姿态估计不稳。
- **关键点相对位移**：手腕相对肩 / 髋的位移，捕捉挥拍轨迹幅度。
- **重心轨迹**：髋中心（MediaPipe 的 `world_landmarks` 原点）位移与速度。
- **节奏 / 时序统计量**：动作时长、峰值数量与间隔、起止速度比。

### 4. 时序分割与对齐

- **滑窗 + 峰值检测**：对"手腕速度"这类一维信号平滑后找局部极大值，就是最朴素的**击球瞬间检测**。手腕类动作识别普遍用轻量滑窗先定位感兴趣区间再分类[BadminSense (CHI 2026)](https://dl.acm.org/doi/full/10.1145/3772318.3790998)。
- **DTW（动态时间规整）**：不同时长的序列不能直接算欧氏距离。DTW 构造 `n×m` 代价矩阵，用动态规划找一条从 `(0,0)` 到 `(n,m)` 的单调连续路径，把两个序列"拉伸对齐"后累加距离，得到与时长无关的相似度。`window` 限制弯曲幅度，`use_pruning` 剪枝加速[dtaiDistance](https://pypi.org/project/dtaidistance/)。
- 常见误解：DTW 是**度量**不是分类器——它只告诉你"这段和模板差多少"，分类要靠最近邻模板或把 DTW 距离矩阵喂给 KNN / 聚类。

# 骨架 → 特征 → 击球瞬间 → DTW 匹配 的最小骨架代码
import numpy as np, cv2
import mediapipe as mp
from mediapipe.tasks import python as mp_python
from mediapipe.tasks.python import vision
from scipy.signal import find_peaks
from dtaidistance import dtw

# 1) 逐帧提骨架（mediapipe 1.x 用 Tasks API，需要单独下载 pose_landmarker.task 模型文件）
opts = vision.PoseLandmarkerOptions(
    base_options=mp_python.BaseOptions(model_asset_path="pose_landmarker_full.task"),
    running_mode=vision.RunningMode.VIDEO,
    num_poses=1)
landmarker = vision.PoseLandmarker.create_from_options(opts)

def angle(a, b, c):                     # b 为顶点，如 (肩, 肘, 腕) 求肘角
    v1, v2 = a - b, c - b
    cos = np.dot(v1, v2) / (np.linalg.norm(v1) * np.linalg.norm(v2) + 1e-9)
    return np.degrees(np.arccos(np.clip(cos, -1.0, 1.0)))

# 2) 击球瞬间：手腕速度的峰值
wrist = seq[:, WRIST_IDX, :]                      # (T, 3) 世界坐标
speed = np.linalg.norm(np.diff(wrist, axis=0), axis=1)
speed = np.convolve(speed, np.ones(5) / 5, mode="same")   # 平滑，抑制抖动误检
hits, _ = find_peaks(speed, height=np.percentile(speed, 90), distance=8)

# 3) 对齐不同时长：把每段动作重采样到固定帧数，再算 DTW 距离
def resample(a, n=60):
    t = np.linspace(0, 1, len(a)); tn = np.linspace(0, 1, n)
    return np.stack([np.interp(tn, t, a[:, d]) for d in range(a.shape[1])], axis=1)

d = dtw.distance_fast(resample(seq_a).ravel().astype(np.double),
                      resample(seq_b).ravel().astype(np.double),
                      use_pruning=True)

## 两条路线适用条件对比

| 维度 | 学术路线（GCN / PoseC3D） | 工程路线（特征 + DTW / 分类器） |
|---|---|---|
| 需要的样本量 | 每类数千条起，NTU120 有 113,945 样本 / 120 类 | 每类 30–100 条即可起步 |
| 标注要求 | 整段视频一个动作类别标签，动作需预先切好 | 只需标"击球在第几帧" + 类别 |
| 8GB 显存可行性 | 单卡 batch 16 的 ST-GCN 尚可；PoseC3D（SlowOnly-R50）吃紧 | CPU 都能跑 |
| 训练时间 | 数小时到数天 | 秒级到分钟级 |
| 可解释性 | 差，只能给类别和置信度 | 好，能说"你的肘角比模板小 15°" |
| 对姿态估计噪声 | GCN 敏感，PoseC3D 较鲁棒 | 同样敏感，但平滑 + 角度特征能压住 |
| 迁移到羽毛球 | 需要重新标注目标域，NTU 里没有羽毛球类别 | 直接定义羽毛球专属特征，无迁移问题 |

**结论：自己录几百段、无大规模标注 → 工程路线为主。学术路线只做两件事**：借 PoseC3D 那类对噪声鲁棒的表示思路，以及在有几千条标注后再考虑微调。

### 一步步怎么做

1. **固定拍摄协议**：机位、距离、高度、帧率写进 README，否则特征不可比。
2. **切分**：用击球声或人工粗标，把录像切成"单次击球"片段（建议击球前 0.5s ~ 后 0.5s）。
3. **提骨架**：MediaPipe 逐帧跑，存成 `(T, 33, 3)` 的 `.npy`，留一份可视化供人工检查。
4. **清洗**：`visibility` / `presence` 过低的帧插值补回；坐标做 5 帧滑动平均。
5. **特征化**：每段算 10–20 维汇总特征（各关节角均值 / 极值 / 到达极值的时刻、角速度峰值、重心位移、时长）。
6. **定位击球**：手腕速度峰值检测，人工校验 20 段，调 `height` / `distance`。
7. **分类**：先 `RandomForestClassifier` 建立 baseline（用 `GroupKFold` 按"人 / 场次"分组），再上 XGBoost，最后才考虑 1D-CNN / GRU。
8. **模板匹配**：每类取 5–10 条标准动作作 DTW 模板，输出"离哪个模板最近、差在哪几个特征"。
9. 到这一步之后，再拿几千条数据去微调预训练 GCN。

## 选型建议（针对 8GB 显存）

- **8GB 是明确的约束线**。PoseC3D 官方配置是 8×GPU、batch 16、uniform 48 帧，单卡 8GB 大概率 OOM；ST-GCN / STGCN++（1.39M–3.1M 参数）单卡 batch 8–16 更现实。
- **RTX 4060 Laptop 是 Ada 架构 sm_89，必须选 CUDA 11.8 及以上的 PyTorch wheel**（cu124 稳妥）。装完先验证：`python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"`。
- **不要为这个任务买云 GPU**。瓶颈是标注量和拍摄规范，不是算力。
- GPU 只在训练 GRU / 微调 GCN 时才需要，特征工程全在 CPU 上跑。

## 常见坑

1. **把 NTU 预训练权重直接用在羽毛球上**。NTU 的 60/120 类里没有羽毛球挥拍，输出层完全不对；且关节定义（25 vs 33）不一致，必须先映射并重训分类头。
2. **用 2D 像素坐标算角度**。透视畸变带来系统性偏差，用 `world_landmarks`，或至少先按身体尺度归一化。
3. **不按"人/场次"分组做交叉验证**。同一视频的相邻帧高度相似，随机划分会让准确率虚高 20 个点以上。
4. **直接对原始骨架序列算 DTW**。维度高、噪声大，DTW 会退化；先降维成角度/速度再算。
5. **混淆"击球瞬间检测"和"动作分类"**。前者是时序分割（滑窗 + 峰值），后者是分类；先做对前者，否则分类器学的是"哪几帧像挥拍"而不是"这拍是什么球"。
6. **mmcv 与 torch 版本不匹配**。用 `mim install mmcv` 而不是 `pip install mmcv`，否则 import 时直接崩。
7. **MediaPipe 1.x 需要单独下载 `.task` 模型文件**，它不在 pip 包里。
