## 三、三条最重要的心法（如果只记三件事）

### ① 单目手机视频**算不出**生物力学真值 —— 先把项目定位改对

论文里的关节角度、躯干旋转、鞭打时序，**全部来自 3D 运动捕捉**。
单目 2D 有系统性低估（对照研究测得髋约 −11.2°、膝约 −10.6°）。

**你要做的是"画面投影指标的纵向对比"**，不是生物力学测量。
这个定位一变，你的报告立刻从"不严谨"变成"诚实的工具"。

> 那 6 份调研笔记里，有两个 agent 把"算关节角度"当核心卖点，
> 另外两个明确说"单目算不出真值"—— **它们直接矛盾**，
> 而这个矛盾只有交叉审校环节才被发现。
> 详见 `part1-多agent协作/05-实战复盘.md` 的案例 B。

### ② 多 agent 买到的不是"更聪明"，是"隔离 + 并行 + 独立视角"

**唯一真正变强的地方是"验证者"**：一个 agent 写，另一个专门挑错。

因为 AI 会给自己的产出背书 —— 让它"再检查一遍"，它倾向于说"没问题"。
换一个没有那段上下文的 agent，它才真的会挑错。

> **实测数据**：6 个调研 agent + 1 个审校 agent，抓到 43 条错误。
> 单靠任何一个写手 agent 自查，一条都抓不出来。

### ③ 你不需要会调试，但你必须会「喂料」

AI 助手看不到你的屏幕。**它只能根据你给的信息推理。**

一条铁律：**永远贴完整的报错**（从 `Traceback` 到最后一行），
不要只说"跑不起来"。模板在 `part2-YOLO与骨架/05-常见坑与调试.md` 第六节。

再加一招，效果翻倍：**让助手先诊断，不要它马上改。**
> "先不要改代码。请先列出这个现象最可能的 3 个原因，按可能性排序，
> 以及每个原因我要运行什么命令来确认。等我确认了再改。"
>
> 这一招能避免它对着错误的原因改十遍。

### 跑通的过程中抓到了自己的四个 bug

**这不是缺点，这是"必须真的跑一遍"的理由。** 四个 bug 全部写进了教程：

**属于数据/算法类的两个：**

1. **把 `track_id = -1` 当成了一个球员。**
   跟踪器不给每个检测框都分配 id。341 帧的真实视频里 1014 行有 323 行（31.9%）没有 id。
   旧代码把它们串成一条序列，**不同人的坐标被接在一起**，
   算出 **239 肩宽/秒**的假速度，然后当成 7 次"击球"写进了报告。
   → 修复：`03` 默认剔除 `track_id < 0` 的行。教训写进 `part2/03`。

2. **条形图的横轴刻度没意义。**
   用 `np.arange(n) + i*0.35` 当横坐标，轴上出现了 `0.00/0.25/0.50` 这种刻度。
   → 修复：整数位置 + 偏移，刻度改成整数。

**属于 Windows 环境类的两个（更容易浪费一整晚）：**

3. **`Activate.ps1` 报"禁止运行脚本" → `python` 指向系统 Python。**
   PowerShell 默认禁止 `.ps1`，所以虚拟环境**根本没激活**。
   但你看到的报错是 `ModuleNotFoundError: No module named 'pandas'` ——
   **它把你引向"是不是没装"这个完全错误的方向**（其实装了，装在 `.venv` 里）。
   → 修复：新增 `run.cmd` 启动器（`.cmd` 不受执行策略限制），
   并让三个脚本在导入失败时**自我诊断**，直接告诉你"真正的问题是你用错了解释器"。

4. **`cmd.exe` 用 GBK 读 `.bat`，我写的中文注释被当成命令执行了。**
   表现为刷屏的 `'xxx' is not recognized as an internal or external command` 死循环。
   → 修复：`run.cmd` 改为**纯 ASCII**。
   同时发现本机是 **Windows PowerShell 5.1**，它读**无 BOM** 的 `.ps1` 会按 ANSI 解析，
   中文全部乱码 → 给 `setup.ps1` 加了 UTF-8 BOM。

> **这四个 bug 都不是"想"出来的，是"跑"出来的。**
> 静态检查、语法检查、代码审阅**全都通过了**——它们照样跑错。
> 想省时间的话，记住这条顺序：**先让它在最小输入上跑通，再去处理真实数据。**
