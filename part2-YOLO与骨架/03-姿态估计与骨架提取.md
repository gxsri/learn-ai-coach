## 一、先选对方案

| 方案 | 关键点 | 安装 | 许可证 | 多人 | 新手建议 |
|---|---|---|---|---|---|
| **Ultralytics YOLO-pose** | COCO 17 | `pip install ultralytics` | **AGPL-3.0** | ✅ 内置 | ✅ **主力，就用它** |
| MediaPipe Pose | 33 点 + 世界坐标 | `pip install mediapipe` | Apache-2.0 | ❌ **单主体** | ⚠️ 只用来"第一天看见骨架" |

| MoveNet | COCO 17 | TensorFlow 生态 | Apache-2.0 | ❌ 单主体 | ❌ 不必 |

### 为什么是 YOLO-pose

**一句话：它一个模型同时给你三样东西——多人检测框、17 个关键点、稳定的跟踪 id。**

这对羽毛球场景（画面里 2-4 人）是决定性的。MediaPipe 只能处理一个人，
双打场景直接出局。

### ⚠️ MediaPipe 的唯一合法用途

MediaPipe 装起来最简单、跑得最快，**适合第一天用来"看见骨架长什么样"**，建立直觉。

但请注意：**它的输出不能进入你的正式管线**，因为它是单主体方案。
用它跑双打视频，你会得到"随机跟随某一个人"的诡异结果。

> 另外提醒：**MediaPipe 的依赖是 `opencv-contrib-python`**，
> 它和 `opencv-python` / `opencv-python-headless` **不能共存**（共用 `cv2` 命名空间，会互相覆盖）。
> 装 MediaPipe 之前先想清楚你的环境里留哪个。

## 二、Top-down 还是 Bottom-up

| 范式 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| **Top-down（自顶向下）** | 先检测出每个人的框，再对每个框单独跑单人姿态 | 精度高、**绝不串人** | 人越多越慢（耗时正比于人数） |
| **Bottom-up（自底向上）** | 一次前向出所有人的热力图，再用匹配算法把人拼起来 | 耗时与人数无关 | 人挤在一起时**容易把手脚接到别人身上** |

**羽毛球场景选 Top-down，不要犹豫。** 理由：画面里只有 2-4 个人，
"人越多越慢"这个缺点对你完全不存在；而"绝不串人"这个优点是刚需。

YOLO-pose 内部就是 top-down，你不用自己拼装。

## 三、羽毛球视频的四个特殊困难

### 困难 1：运动模糊

羽毛球挥拍速度极快，普通手机视频里手和球拍经常糊成一片。

- **能控制拍摄**：把快门调到 **1/1000 秒以上**（手机的"运动模式"或专业模式），缩短曝光
- **不能控制拍摄**：靠后处理——置信度过滤 + 平滑。**但要接受精度损失**

### 困难 2：遮挡

球员自己挡住手臂、两人交叉、球拍挡住身体。

- **做法**：置信度低于阈值的点**直接丢掉**，不要用它算角度
- ❌ **不要**把 `score=0.1` 的手腕当成真值去算击球角度
- ⚠️ **不要静默插值填补**——填出来的数据看起来平滑，但它不是测量结果。要插值就**单独标记**这一帧是"推测帧"

### 困难 3：左右手不分

模型输出的 `left_*` / `right_*` 是**球员自己身体的左右**。
球员背对镜头时，画面左边的是他的**右手**。

- 做左右手技术统计时，**必须用躯干朝向校正**

### 困难 4：不能拿框的宽高当"身高"

杀球时手臂高举、腿大幅伸展，检测框会剧烈变化。
**用框宽高做尺度归一化会引入巨大误差。**

- ✅ **正确做法**：用**肩宽**（关键点 5-6 的距离）或**髋宽**（11-12 的距离）做尺度基准
- 这两个点在各种动作下相对稳定

## 四、最小可运行：视频 → CSV

```python
"""extract_pose.py —— 从视频提取骨架，存成 CSV"""
import csv
import cv2
from ultralytics import YOLO

VIDEO = 'badminton.mp4'
OUT   = 'outputs/demo/01_pose.csv'

# ① 加载模型。首次运行会自动下载权重。
model = YOLO('yolo26n-pose.pt')

# ② track 而不是 predict —— 带跟踪 id，这是跨帧分析的前提
results = model.track(
    source=VIDEO,
    persist=True,      # 跨帧保持跟踪状态
    stream=True,       # 逐帧流式返回，不要把整个视频加载进内存
    verbose=False,
)

rows = []
for frame_idx, r in enumerate(results):
    if r.keypoints is None or r.keypoints.xy is None:
        continue                       # 这一帧没检测到人

    xy   = r.keypoints.xy.cpu().numpy()      # [人数, 17, 2] 像素坐标
    conf = r.keypoints.conf.cpu().numpy()    # [人数, 17]   置信度
    ids  = r.boxes.id                        # [人数] 跟踪 id，可能是 None

    for person_idx in range(xy.shape[0]):
        track_id = int(ids[person_idx]) if ids is not None else -1
        row = {'frame': frame_idx, 'track_id': track_id}
        for k in range(17):
            row[f'x{k}'] = float(xy[person_idx, k, 0])
            row[f'y{k}'] = float(xy[person_idx, k, 1])
            row[f'c{k}'] = float(conf[person_idx, k])
        rows.append(row)

# ③ 写 CSV
if rows:
    with open(OUT, 'w', newline='', encoding='utf-8') as f:
        writer = csv.DictWriter(f, fieldnames=list(rows[0].keys()))
        writer.writeheader()
        writer.writerows(rows)

print(f'完成：{len(rows)} 条记录 → {OUT}')
```

**跑通标志**：`01_pose.csv` 里每一行是"某一帧的某一个人"，
带 17 个点的 x/y/置信度，以及一个 `track_id`。

完整可运行版本在 `../starter/02_extract_pose.py`（多了参数解析、进度输出、错误处理）。

## 五、拿到关键点之后，**必须**做这四件事

新手最大的错误是"拿到坐标就直接算角度"。**这四步不做，你的指标一定是垃圾。**

### 第 1 步：检查跟踪是否稳定

**先看 `track_id` 有没有频繁跳变。**

```python
import pandas as pd
df = pd.read_csv('outputs/demo/01_pose.csv')
# 每个 id 出现在多少帧里
print(df.groupby('track_id')['frame'].agg(['count', 'min', 'max']))
```

**正常的画面**：2 个 id，每个出现几千帧，帧号连续。
**不正常的画面**：出现了 50 个 id，每个只出现十几帧 —— 说明跟踪一直在断。

### ⚠️ 还有一个必须检查的东西：`track_id = -1`

**跟踪器不保证给每个检测框都分配 id。** 新出现的人、置信度边缘的框、
被遮挡后重新出现的框，都可能拿不到 id。

本教程的 `02_extract_pose.py` 用 `-1` 作哨兵值标记这些框。**但 `-1` 不是"一个球员"。**

```python
# 有多少行没有 track_id？
print('无 id 的行数:', (df['track_id'] < 0).sum())
```

> **这是实机踩到的真 bug，不是假想的风险。**
>
> 用一段 341 帧的真实行人视频测试时，1014 行里有 **323 行没有 id**（31.9%）。
> 早期版本的 `03` 脚本把它们全当成"球员 -1"串成一条时间序列，
> 于是**不同人的坐标被接在一起**，逐帧差分算出 **239 肩宽/秒**的离谱速度，
> 然后被当成 7 次"击球"写进了报告。
>
> 修复方式：`03` 默认**剔除**所有 `track_id < 0` 的行（加 `--include-untracked` 可强制保留）。
> 修复后，那个虚假的"球员 -1"和它的 182.7 肩宽/秒峰值一起消失了。
>
> **给你的通用教训**：
> **"缺失的身份"和"某一个身份"是两回事。**
> 任何用哨兵值（-1、0、空字符串）代表"未知"的地方，
> 都要想清楚它会被下游当成一个**真实的个体**还是**一堆混合体**。
> 前者能算，后者算出来的东西**一定是垃圾**。

> **跟踪断了怎么办**：改用更合适的跟踪器、降低检测置信度阈值、提高视频质量。
> 但要知道：**跟踪不稳 = 后面全废**，这一步必须解决。

### 第 2 步：置信度过滤

```python
CONF_THRESHOLD = 0.5
# 低于阈值的点标记为"不可用"
valid = df['c9'] >= CONF_THRESHOLD          # 以左手腕为例
```

**丢掉，不要填。** 需要连续曲线的地方（比如算速度），
**填的值要能区分出来**——至少加一列 `interpolated` 布尔标记。

### 第 3 步：平滑（关键！）

关键点逐帧会抖。**对原始坐标直接做差分算速度，得到的全是噪声。**

**用 Savitzky-Golay 滤波**：它在平滑的同时能保留峰值的形状——
这正是你要的，因为"击球"就是一个速度峰值。

```python
import numpy as np

def savgol_smooth(y, window=11, polyorder=2):
    """滑动窗口多项式拟合。window 必须是奇数，且 > polyorder。"""
    n = len(y)
    half = window // 2
    out = np.array(y, dtype=float)

    # 用多项式拟合每个窗口的中心点，窗口不足时用可用范围
    for i in range(n):
        lo = max(0, i - half)
        hi = min(n, i + half + 1)
        xs = np.arange(lo, hi)
        if len(xs) <= polyorder:
            continue
        coeffs = np.polyfit(xs, y[lo:hi], polyorder)
        out[i] = np.polyval(coeffs, i)
    return out
```

> **`window` 怎么选**：太小（3-5）几乎没效果；太大（>21）会把真实的峰值抹平。
> 视频帧率 30fps 时，**从 11 开始试**。
> 判断标准：画出平滑前后的曲线叠在一起，**平滑后应该仍然看得出峰，而不是变成一条平线**。

> **不要用简单的移动平均代替。** 移动平均会把峰值削平——而峰值正是你要检测的东西。

### 第 4 步：尺度归一化

不同距离、不同身高的球员，像素坐标不能直接比。

**用肩宽归一化**：

```python
shoulder_width = np.hypot(df['x5'] - df['x6'], df['y5'] - df['y6'])
# 之后所有位移量都除以 shoulder_width
relative_displacement = displacement / shoulder_width
```

## 六、3D 姿态：现在值不值得学

**结论：不值得投入主力时间，但值得"知道"。**

| 方案 | 现状 |
|---|---|
| MediaPipe 的 `pose_world_landmarks` | 给你米制 3D 坐标，但是**"伪 3D"**——单目估出来的相对深度，尺度靠人体先验猜，抖动明显、绝对位置不可信。零成本，可做**定性趋势观察** |
| MotionBERT（ICCV 2023） | 把 2D 序列"提升"到 3D。官方环境写死 Python 3.7 + PyTorch 1.9 + CUDA 11.6 —— 典型的"论文复现环境"，和你的新显卡驱动大概率要打架 |
| SMPL 系 | 输出完整人体网格，是"动捕级"路线。学习曲线是 2D 的数倍 |

**为什么现在不学**：

1. 你的羽毛球指标（击球时刻、投影角度、髋中心位移）在 2D 上就能算，
   而且**误差主要来自拍摄质量和关键点置信度，不是缺失的第三维**
2. 3D 提升模型的**误差和抖动会直接污染你的角度曲线**——
   你会分不清"是运动员变了"还是"是模型抖了"
3. 等 2D 管线稳定后，MotionBERT 只需要**接在你的 2D 输出后面**，是个可插拔的增量，
   不是必须重做的地基
